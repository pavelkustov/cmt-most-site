# Сайт ЦМТ «Мост»

Сайт Центра междисциплинарных технологий «Мост» физического факультета Университета ИТМО.
Сверстан по макету в Figma. Статический сайт на HTML, CSS и JS без сборки, публикуется через GitHub Pages.

## Страницы

| Файл | Что это |
|---|---|
| `index.html` | Главная: о центре, наука, индустрия, образование, новости |
| `direction.html?id=puf` | Страница научного направления (id из `assets/js/data.js`) |
| `publications.html` | Все публикации с поиском, фильтрами и видом «карточки / список» |
| `news.html` | Новости, новость месяца и попап (`news.html?open=<id>` открывает новость сразу) |
| `404.html` | Страница «не найдено», GitHub Pages отдает ее на любой несуществующий адрес |

## Как посмотреть локально

```powershell
cd "$HOME\OneDrive\Рабочий стол\cmt-most-site"
python -m http.server 8000
```

Затем открыть http://localhost:8000. Сайт нужно открывать через сервер, а не двойным кликом по файлу.

## Как менять контент

Весь контент лежит в `assets/js/data.js`:

- `DIRECTIONS` содержит научные направления (карточки на главной и страницы направлений).
  Фон страницы направления берется из `hero`, а если его нет, из `image` карточки.
  `heroTitle` задает заголовок первого экрана: курсивная часть в `<em>`, перенос через `<br>`,
  строка, которая не должна переноситься даже шире границы, оборачивается в `<span class="line">`;
- `PUBLICATIONS` содержит публикации, новая добавляется копированием любого объекта.
  После добавления запустите `python tools/fetch_citations.py`: он скачает из Crossref по DOI данные для окна
  «Цитировать» (ГОСТ, MLA, APA, BibTeX, EndNote, RefMan, RefWorks) в `assets/js/citations.js`.
  Без этого цитата соберется из полей `data.js`, но без тома, номера и страниц.
  Откуда брать новые работы: `python tools/fetch_publications.py` собирает статьи сотрудников
  из OpenAlex, профилей ORCID и Crossref в `docs/publications_db.json`, а
  `python tools/publications_to_data.py` переносит из базы в `data.js` те, которых там еще нет
  (что вошло в базу и чего не хватает — в `docs/CONTENT_GAPS.md`).
  Дальше `python tools/enrich_publications.py` проставляет работам квартиль журнала и число
  цитирований: квартиль из выгрузок SJR (файлы «scimagojr ГОД.csv» рядом с репозиторием,
  берется лучший квартиль за самый свежий год, где журнал есть в рейтинге), цитирования
  из `docs/publications_db.json`. Разобранная карта «журнал — квартиль» остается
  в `docs/journal_quartiles.json`, поэтому без выгрузок скрипт тоже работает.
  У сборников конференций и препринтов квартиля нет, у русских журналов рейтинга SJR нет:
  они перечислены в словаре `MANUAL` внутри скрипта и проставляются руками;
- `NEWS` содержит новости, у новости месяца стоит `featured: true`;
- абстракты публикаций лежат отдельно, в `assets/js/abstracts.js` (ключ — DOI), и собираются
  `python tools/fetch_abstracts.py`: сначала из `docs/publications_db.json` (там абстракты
  OpenAlex), затем из Crossref для тех работ, у которых в базе пусто. Текст берется как
  у издателя и не переводится, язык оригинала сохраняется. На карточке публикации абстракт
  свернут до высоты картинки и раскрывается по клику. Чего не нашлось нигде, скрипт выписывает
  в `docs/ABSTRACTS_MISSING.md` со ссылками на статьи: туда вставляется абстракт со страницы
  издателя, а `python tools/fetch_abstracts.py --import-md` переносит его
  в `docs/abstracts_manual.json`, откуда он попадает на сайт и переживает пересборку;
- названия публикаций чистит `python tools/fix_titles.py`: в них попадает разметка издателя
  (`<sub>`, `<i>`, TeX `CaCO$_3$`, запись `-=SUB=-2-=/SUB=-`) и оторванные подстрочные индексы
  вроде «CsPbBr 3». Формулы со смешанным регистром на карточке не переводятся в верхний
  регистр, это делает `titleHTML` в `main.js`;
- даты публикаций уточняет `python tools/fix_dates.py` по Crossref, но день он подставляет
  только внутри того же месяца: у многих работ Crossref знает лишь дату выкладки онлайн.
  Чего не хватает, скрипт выписывает в `docs/DATES_MISSING.md` со ссылками на статьи;
  туда вписывается дата со страницы издателя (понимаются 15.12.2026, 2026-12-15
  и 15 December 2026), а `--import-md` переносит ее в `docs/dates_manual.json` и в данные.
  Вписанное не теряется при перегенерации списка;
- тексты направлений удобнее править не в данных, а в `docs/DIRECTIONS_TEXT.md`:
  `python tools/directions_text.py --export` выгружает туда название, подзаголовок, абзацы,
  ключевые слова и команду всех направлений, `--import` заливает правки обратно в `data.js`
  (`--import --dry` покажет, что изменится). Заголовок первого экрана (`heroTitle`) там не
  правится, он с версткой и меняется отдельно;
- метрики направления (публикации, цитирования, индекс Хирша, доля статей в Q1 и Q2, статьи
  за последние три года) не хранятся в данных, а считаются в `main.js` по работам направления.
  Руками задается только `team` — размер команды из анкеты;
- `PEOPLE` содержит сотрудников центра: имя с фамилией, степень или ступень обучения и должность.
  Источник — книга «ЦМТ Мост.xlsx» рядом с репозиторием, переносит `python tools/people_from_book.py`
  (`--dry` покажет, что изменится). Из книги берутся только имя, степень и должность, почты,
  телефоны, даты рождения и научные идентификаторы в репозиторий не попадают. Запускать после
  каждого обновления книги, например когда все перешли на следующий курс. Направления ссылаются сюда по имени,
  поэтому должность правится в одном месте. Порядок в команде на странице направления задает
  не порядок в данных, а правило в `main.js`: доктора наук, кандидаты наук, аспиранты,
  магистры, студенты, бакалавры, внутри ступени раньше тот, кто старше по курсу.

Картинки кладутся в `assets/img/` (лучше в WebP, до 300 КБ), в данных указывается только имя файла.

Новую страницу направления, когда она наполнится содержимым, надо дописать в `sitemap.xml`.

## Шрифты

Inter и Roboto лежат в репозитории (`assets/fonts`, подключены в `assets/css/fonts.css`), а не грузятся
с Google Fonts: из России так быстрее и сайт не зависит от внешнего сервиса. Обновить набор:

```powershell
python tools/fetch_fonts.py
```

В именах файлов есть хэш содержимого, поэтому после обновления надо поправить две ссылки
`rel="preload"` в `<head>` каждой страницы.

## Проверка перед публикацией

```powershell
python tools/bump_assets.py    # метки версий ?v= у CSS/JS, чтобы браузеры не показывали старый кэш
python tools/smoke.py          # ошибки JS, битые картинки, горизонтальный скролл, фильтры, попап
python tools/smoke.py --shots  # то же и скриншоты в tools/shots/
```

Нужен Python с `playwright` (`pip install playwright` и `playwright install chromium`).

## Публикация на GitHub Pages

1. Создать репозиторий на GitHub и запушить ветку `main`.
2. Settings → Pages → Source: *Deploy from a branch*, ветка `main`, папка `/ (root)`.
3. Через 1–2 минуты сайт будет доступен по адресу `https://<аккаунт>.github.io/<репозиторий>/`.

Все пути в сайте относительные, поэтому он работает и в подпапке репозитория, и на своем домене.

## Структура

```
index.html, direction.html, publications.html, news.html, 404.html
robots.txt, sitemap.xml  для поисковиков
assets/css/style.css     стили (1rem = 10px на ширине 1920, дальше масштабируется)
assets/css/fonts.css     подключение шрифтов из assets/fonts (собирает tools/fetch_fonts.py)
assets/js/data.js        контент
assets/js/layout.js      шапка, подвал, иконки, типографика (предлоги не висят в конце строки)
assets/og                картинки превью ссылок 1200x630 (tools/make_share_images.py рисует их и PNG-иконки)
assets/icons/favicon.svg иконка сайта: мост из логотипа, перерисован в вектор
assets/js/main.js        логика страниц
assets/img, assets/icons картинки и иконки из Figma
design/                  скрипты выгрузки картинок из Figma (рендеры макета и исходники только локально)
docs/PROJECT.md          информация по проекту и список открытых вопросов
tools/                   смоук-тест и вспомогательные скрипты
```

Проверка опубликованного сайта: `python tools/smoke.py --base https://pavelkustov.github.io/cmt-most-site/`
