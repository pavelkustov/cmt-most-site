# Переезд сайта на свой сервер

Сайт статический: на сервер копируется одна папка `dist/`, которую собирает `tools/build.py`.
Ни базы данных, ни серверного кода нет. Нужен любой веб-сервер, ниже пример для nginx.

## 1. Собрать сайт под новый адрес

```powershell
python tools/build.py --url https://НОВЫЙ-ДОМЕН/
python tools/smoke.py
```

Адрес подставляется в ссылки для поисковиков и соцсетей (canonical, og, sitemap, robots)
и в тег `base` страницы «не найдено». Чтобы адрес стал постоянным, его надо поменять
в `content/site.json` (поле `url`): тогда и GitHub Actions, и локальная сборка возьмут его сами.

Если сайт будет жить не в корне домена, а в папке (например `https://itmo.ru/bridge/`),
в `--url` пишется адрес с папкой. Все пути внутри сайта относительные, отдельно их менять не нужно.

## 2. Скопировать на сервер

Содержимое `dist/` целиком в папку сайта на сервере, например `/var/www/cmt-most`.
Больше ничего из репозитория на сервер класть не нужно: исходники, скрипты и рабочие файлы
в `dist/` не попадают.

## 3. Настроить nginx

- `deploy/cmt-most-security.conf` положить в `/etc/nginx/snippets/`;
- `deploy/nginx.conf` взять за основу конфигурации сайта: вписать домен, пути к сертификату
  и папку сайта (`root`);
- `nginx -t` и перезагрузить nginx.

Что дает конфигурация: HTTPS с переадресацией с HTTP, сжатие, долгий кэш для файлов
с меткой версии, страница 404 на любой несуществующий адрес и заголовки безопасности
(CSP, запрет встраивания в чужие страницы, HSTS, nosniff, Referrer-Policy).

## 4. Проверить

```powershell
python tools/smoke.py --base https://НОВЫЙ-ДОМЕН/
```

Заголовки безопасности можно посмотреть на securityheaders.com или командой
`curl -I https://НОВЫЙ-ДОМЕН/`.

## Если сайт остается на GitHub Pages

Публикует GitHub Actions (`.github/workflows/deploy.yml`): пуш в `main` собирает сайт,
прогоняет смоук и выкладывает `dist/`. Заголовки сервера GitHub Pages задать не дает,
поэтому там действует только политика из `<meta>` страниц (без `frame-ancestors` и HSTS).
